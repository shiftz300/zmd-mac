# 排障

## 安装失败

先运行 `./zmd doctor` 检查架构、系统版本与 Rosetta，再运行 `./zmd verify` 检查内置文件。
SHA-256 清单能发现损坏，不代替发布者身份签名。
安装日志写入 `~/Library/Logs/zmd-mac/install-*.log`。

较早手工包装的应用可能不支持 HUD / MSync 配置文件；CLI 会提示升级包装层，
不会声称这些设置已经生效。新安装器生成的应用包含这些功能。

只支持终末地国服官方启动器安装 EXE，当前已验证 1.6.0 的 NSIS 布局。
官方修改布局时会拒绝安装，应更新安装器；不要用任意游戏 EXE 替代。
本地 EXE 可使用 `--sha256` 对照你已有的可信校验值。未提供时只记录哈希。

安装器在临时目录初始化全新 prefix，完成后才移到目标路径。失败会清理它自己的临时 prefix，
不会终止其他 Wine 应用。原有同名应用始终保留。

## 提示需要官方启动器 / 10100

关闭直接运行的游戏，双击生成的 .app，再从官方启动器点「开始游戏」。
国服需要启动器传入授权信息；不能直接执行 `Endfield.exe`。

## FSR 黑色网纹

在当前报告中切换 TAAU 会消失，建议先用 TAAU，参见 [调优](tuning.md)。
若 TAAU 也有同样纹理，再检查是否固定于某个材质／场景，不要直接认定是 FSR。

## 应用列表里没有图标

先在 Finder 的 `~/Applications` 中确认应用是否存在。开发目录里的应用与 Finder 替身可能尚未被系统收录。
从 0.5.2 起，应用使用普通应用标记，安装完成后主动注册到系统应用列表；运行时再隐藏包装层的 Dock 图标。
从 0.5.4 起，安装包里的空白模板保持隐藏，只有安装完成的官方启动器会注册到应用列表。
旧安装不会因下载新 PKG 自动更新，请勿覆盖含有游戏数据的应用。

## Dock 退出

包装层是后台应用，没有独立的 Dock 图标。实际窗口显示为「鹰角启动器」和「终末地」。
两个图标的退出请求都转给当前会话的后台入口，但仅关闭被点击的应用。
游戏退出走主窗口正常关闭请求，保留启动器；启动器退出走自身 Qt 托盘退出动作，
让辅助进程随它结束，保留游戏。运行设置里的重启／缓存清理才会依次退出整个会话。
包装层不显示退出角标或选择框。如果游戏取消或长时间没有完成退出，包装层会取消本次等待；
处理游戏自身的提示后可以再次退出，也可以在游戏内退出。包装层不会因超时强行终止游戏。

若升级后仍出现白色图标或名称仍为 wine，确认整个旧会话已经退出，并使用新运行库重开。
仅替换 Swift 入口不够：构建产物还需要 `wine-session-dock.patch` 和相应 Wine 模块。
从 0.7.0 升至 0.7.1 的分别退出改动仅需更新原生入口；现有 Wine 模块可复用。旧后台入口需退出后重开才会加载新逻辑。
`native-launcher-*.log` 中的 `Dock quit received`、`Application quit started/completed`、`Session quit started` 和
`Native quit requested` 可用于区分请求未送达与程序未完成退出。日志不记录启动参数或令牌。

## 日志与提交问题

PKG 显示失败时，在系统安装器「窗口 → 安装日志」选择全部日志。
若提示目标已存在，请取消对应服，保留原应用；自定义输出目录或本地 EXE 使用 ZIP 内的 CLI。
若下载失败，可重新安装该服；最终 `.app` 仅在初始化全部完成后写入，已有应用不会覆盖。
安装脚本日志也会写到当前用户的 `~/Library/Logs/zmd-mac`。

应用日志位于 `.app/Contents/SharedSupport/logs`。游戏日志、启动器日志和注册表可能包含
账号与授权信息；报告时优先附 `./zmd inspect --app ...`，仅复制必要、脱敏后的错误片段。
不要把已经下载游戏的 .app 或 prefix 上传到 GitHub。
